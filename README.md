# Генерация кода на Visual Prolog: данные с GitHub против учебных примеров

## Задача

Большие языковые модели плохо пишут на Visual Prolog: путают его с обычным Прологом и старыми версиями языка, забывают объявления типов, режимы аргументов и детерминизм. Язык редкий, в обучающих данных моделей его почти нет.

## Гипотеза

Дообучение на учебных примерах вида «пояснение → код» сильнее улучшает синтаксическую правильность, чем дообучение на сыром коде с GitHub.

## Методика

- Базовая модель: Qwen2.5-Coder-1.5B-Instruct.
- Два набора данных: сырой код с GitHub и учебные примеры.
- Два LoRA-адаптера, обучение QLoRA в Google Colab (T4).
- Свой бенчмарк из задач на Visual Prolog с эталонными решениями.
- Метрики: доля решений, которые компилируются (`vipBuilder.exe` из Visual Prolog 11), и правильность результата.

## Что в репозитории, а что нет

В репозитории лежат скрипты сбора и сборки датасета, описание того, как он собран, и результаты. Модель и полный датасет хранятся отдельно.

| Что | Где |
|---|---|
| Скрипты сбора и сборки датасета | этот репозиторий, `src/` |
| Открытая часть данных: код с GitHub, wiki Visual Prolog, учебные примеры, лабораторные ТулГУ | этот репозиторий, `data/` |
| Часть из библиотеки PFC | не публикуется, собирается локально (см. ниже) |
| Полный датасет с частью из PFC | приватная папка на Google Drive автора, используется для обучения в Colab |
| Веса модели (LoRA-адаптер и модель после слияния) | Hugging Face (ссылка появится после публикации) |

### Почему часть данных не публикуется

Самый полезный источник для обучения — исходный код библиотеки PFC (Prolog Foundation Classes), который ставится вместе с Visual Prolog 11: около 3700 файлов `.pro`, `.cl` и `.i`. Это код той же версии языка, что и компилятор, и в нём много того, на чём модели ошибаются: объявления классов и интерфейсов, режимы аргументов, детерминизм.

Лицензия Visual Prolog (`license.htm` в папке установки) разрешает использовать этот код, в том числе для обучения модели, но запрещает распространять сами исходники. Поэтому:

- файлы PFC и записи датасета, собранные из них, в репозиторий не кладутся;
- вместо них в репозитории есть скрипт [`src/collect/collect_pfc.py`](src/collect/collect_pfc.py), который собирает эту часть из Visual Prolog, установленного у пользователя, в `data/raw/pfc/`; эта папка и файлы `data/dataset/pfc_*.jsonl` закрыты в `.gitignore`;
- веса модели публикуются: модель обучена на коде, но не содержит и не распространяет его в виде исходников.

Чтобы получить полный датасет, установите Visual Prolog 11 и пересоберите его по командам из раздела «Пересборка».

### Алгоритмы

Синтаксис Visual Prolog модель после первого дообучения знает сносно, а решать задачи не умеет: на бенчмарке она пишет обрывки кода вместо программы. Поэтому в датасет добавлен набор **алгоритмов** на простых данных (числа, списки, строки, небольшие графы), чтобы модель училась ходу решения, а не только синтаксису.

Каждая задача (`data/raw/algorithms/`) — это:

- условие («Напиши на Visual Prolog …»);
- идея решения простыми словами — что делаем и почему это работает;
- законченная консольная программа `main.pro` для Visual Prolog 11 (`<slug>.pro`);
- ввод и ожидаемый вывод.

Все программы собираются компилятором Visual Prolog 11 и запускаются, их вывод сверяется с эталоном (`python src/eval/check_algorithms.py`). Эталоны проверены вручную.

| Тема | Задачи |
|---|---|
| Числа | НОД и НОК, быстрое возведение в степень, простота, решето Эратосфена, разложение на множители, Фибоначчи, факториал, треугольник Паскаля, Коллатц, системы счисления, целый корень, совершенные числа, FizzBuzz, ввод с клавиатуры |
| Списки и сортировки | сумма, максимум, разворот, повторы, выравнивание, сжатие серий, сдвиг, слияние, сортировки вставками, пузырьком, выбором, слиянием, быстрая |
| Поиск и перебор | бинарный поиск, два числа с суммой, перестановки, подмножества, сочетания, ферзи, подмножество с суммой |
| Строки | палиндром, гласные, шифр Цезаря, анаграммы, частота слов, скобки, римские цифры |
| Графы | все пути (в глубину), кратчайший путь (в ширину), Дейкстра, топологическая сортировка, компоненты связности |
| Динамическое программирование | Кадане, префиксные суммы, размен монет, рюкзак, расстояние Левенштейна |
| Деревья и прочее | двоичное дерево поиска, дерево выражения, матрицы, Ханойская башня, код Грея, разбиение и чередование списков, сортировка подсчётом, голландский флаг, задача Иосифа |
| Логический вывод | родословная (предки, братья и сёстры, двоюродные), экспертная система на правилах, цикл в графе |
| Вещественные числа и разное | корень методом Ньютона, квадратное уравнение, день недели по дате, калькулятор в обратной польской записи, элемент большинства, K-й по величине, максимум в окне, общая подпоследовательность, подстроки, префиксы |

Подробно по источникам и диалектам — [`data/dataset/STATS.md`](data/dataset/STATS.md).

Поля записи: `id`, `source`, `origin` (ссылка или путь), `dialect` (`modern` — Visual Prolog 6 и новее, `legacy` — Visual Prolog 5 и Turbo Prolog), `instruction`, `output`. У пар есть ещё `lang`, `section` и `explanation`.

```json
{"id": "textbook_pairs-00042", "source": "wiki_en", "dialect": "modern", "lang": "en",
 "section": "Lessons/Functions", "explanation": "…", "instruction": "Topic: …\n\n…\n\nWrite the Visual Prolog code.",
 "output": "class predicates\n    makeGreeting : (string Name) -> string Greeting.\n…"}
```

Очистка: служебные комментарии и автокод IDE вырезаются; файлы короче 40 значащих символов (заготовки IDE) и длиннее 20 000 символов отбрасываются; повторы удаляются (файлы сравниваются по коду без пробелов, пары — по пояснению и коду).

## Обучение и результаты

### Как обучить

Ноутбук [`notebooks/train_visual_prolog.ipynb`](notebooks/train_visual_prolog.ipynb) для Google Colab делает всё по кнопке «Выполнить все»: ставит пакеты, берёт данные из этого репозитория (и часть PFC из архива на Google Диске, если он есть), обучает QLoRA-адаптер, рисует график потерь, отвечает на бенчмарк и на отложенные алгоритмы и сохраняет адаптер и ответы на Google Диск. Модель, число эпох и прочие параметры меняются в форме. По умолчанию — Qwen2.5-Coder-7B-Instruct, 2 эпохи, алгоритмы повторяются 3 раза за эпоху; каждый 8-й алгоритм в обучение не попадает и служит честной проверкой.

Ответы модели проверяются компилятором на Windows с Visual Prolog 11:

```bash
python src/eval/check_answers.py answers_v3_algorithms.json
```

Скрипт собирает каждую программу, запускает её и сравнивает ответ с эталоном. В конце печатается таблица «исходная модель / обученная × бенчмарк / отложенные алгоритмы»: сколько ответов компилируется и сколько верны.

### Бенчмарк

[`results/benchmark_v2.json`](results/benchmark_v2.json) — 25 задач (числа, списки, строки, графы, деревья, динамическое программирование, ввод с клавиатуры), которых **нет** в обучающих данных. Каждая задача просит законченную консольную программу и вывод только ответа. Для каждой есть эталонное решение ([`results/benchmark_v2_reference`](results/benchmark_v2_reference)), собранное компилятором, и ожидаемые числа. Ответ модели верен, если её программа компилируется и выводит те же числа в том же порядке; слова вокруг чисел не важны.

Первый бенчмарк ([`results/benchmark_tasks.json`](results/benchmark_tasks.json), 10 задач) оставлен для истории: эталонов в нём нет, а задачи (факториал, Фибоначчи, палиндром и др.) теперь есть среди алгоритмов, поэтому для оценки новых версий он не годится.

### Версии

| Версия | Данные | Потери на проверке | Результат |
|---|---|---:|---|
| [`lora_model`](lora_model) | `textbook_pairs`, 1 эпоха, Qwen2.5-Coder-1.5B | 1,74 | 0 из 10 задач бенчмарка компилируются; в 4 задачах только объявления без правил |
| [`lora_model_v2`](lora_model_v2) | + PFC (исходники и пары «описание → объявление»), 1.5B | 0,96 | училась останавливаться после объявления; эти пары убраны из `pfc_pairs` |
| v3 (ноутбук) | все данные + алгоритмы, 7B | — | ещё не обучена |

Потери разных версий напрямую не сравнимы: у них разные проверочные выборки. Главная метрика — доля ответов, которые компилируются и дают верный результат.

Прежний скрипт обучения первой версии — [`src/train/train_lora.py`](src/train/train_lora.py), её ответы на первый бенчмарк — [`results/benchmark_results.json`](results/benchmark_results.json).

### Проверка гипотезы

В ноутбуке есть параметр `DATA_MODE`: `textbook` — только учебные примеры «пояснение → код», `github` — только код с GitHub, `all` — все данные. Обучите модель в режимах `textbook` и `github` с одинаковыми остальными параметрами и сравните таблицы `check_answers.py`: гипотеза подтверждается, если модель на учебных примерах чаще пишет компилирующиеся и верные программы. Параметр `EVAL_BASE` добавляет к сравнению исходную модель без обучения.

## Структура репозитория

```
data/raw/            собранные источники, только Visual Prolog
data/dataset/        итоговые JSONL-файлы и STATS.md
src/vp_filter.py     определение языка и диалекта
src/collect/         сборщики для каждого источника
src/build_dataset.py сборка датасета
src/train/           первый скрипт обучения LoRA
src/eval/            проверка компилятором: vp_check.py (собрать и запустить программу),
                     check_algorithms.py (набор алгоритмов), check_answers.py (ответы модели),
                     vp_template/ (консольный проект Visual Prolog 11)
notebooks/           ноутбук Colab для обучения и проверки
lora_model*/         обученные адаптеры
results/             бенчмарк v2 с эталонными решениями, первый бенчмарк и ответы модели
```

## Права на данные

Код в `data/` принадлежит его авторам (Prolog Development Center, авторы книг, владельцы репозиториев GitHub) и собран для исследования. Алгоритмы в `data/raw/algorithms` написаны для этого репозитория. Источник каждой записи указан в поле `origin`.
